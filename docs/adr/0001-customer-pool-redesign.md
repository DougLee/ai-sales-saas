# ADR-0001: 客户池与客户表单重设计决策

- 状态：已接受
- 日期：2026-08-14
- 背景：grill-with-docs 会话（依据设计稿《目标客户池列表页》《客户表单-传统CRM风格》20260813）
- 关联 issue：[#1](https://github.com/DougLee/ai-sales-saas/issues/1) [#2](https://github.com/DougLee/ai-sales-saas/issues/2) [#3](https://github.com/DougLee/ai-sales-saas/issues/3) [#4](https://github.com/DougLee/ai-sales-saas/issues/4) [#5](https://github.com/DougLee/ai-sales-saas/issues/5)

## 决策

### 1. 指标条由后端聚合接口计算

页签指标条四格（池子总量+周新增 / 已触达率 / 转化率① / 待核实）新建 `GET /api/companies/metrics` 聚合接口，不做前端拼凑。

- **理由**：已触达率、转化率① 需要跨 Visit/Lead 关联计数，前端算会放大请求数且口径漂移；待核实阈值（7 天）收敛在后端一处。
- **替代方案否决**：只做现有数据能算的指标（口径不完整）；不做指标条（弱化 L0 过程管理价值）。

### 2. 批量操作本期只做认领 + 分配负责人

批量操作条四项中，批量认领、批量分配负责人实现（含后端批量接口）；导出、移入公海按钮置灰（title 提示后续版本）。

- **理由**：认领/分配是公海流转的高频刚需；导出涉及权限与脱敏待定，移入公海已有单个"释放"可用。

### 3. 列表卡片 → 数据表，详情 drawer 全保留

客户列表从卡片式改为「页签+指标条+筛选栏+数据表+分页」传统 CRM 结构；现有详情 drawer（编辑/合并重复/释放/变更历史）与「问小销」入口全部保留。

- **理由**：信息密度需求（一行=三张卡片）；但低频重操作（合并/释放）已有成熟实现，不随布局重构重写。

### 4. 客户表单按稿做四分组，不做存草稿

表单改为①基本信息②联系信息③来源与归属④备注四分组；行业/规模/地区下拉化（预置选项按设计稿，高教为主）；source/ownerId/status 字段露出（状态默认 target 分段控件）；电话失焦实时校验；完整度实时预览；AI 来源条。**不做存草稿**。

- **理由**：客户表字段短（对比线索表单 13 字段），草稿必要性低；schema 字段已齐备，无 DB 改动。
- **「建线索」交互**：直接打开预填客户的线索表单，不做二次确认弹窗。

## 后果

- 客户页信息架构与线索页设计稿风格统一，为后续 L1 线索列表页重写定调。
- completenessScore 前端预览与后端口径需保持对齐（允许近似，以字段填充清单为准）。
- 导出 / 移入公海按钮置灰属于显式欠账，后续以新 issue 跟进。
